# 第二轮作者静态判断：约束早构造与组内反例排程

角色：作者探索，不是独立审核。日期：2026-10-11。未运行 solver、数据库、查询、枚举或模型；未读 reserve；未修改第一轮任何文件。本文读取了第一轮允许暴露的 development.jsonl 六行 source_record、VeriEQL 官方本地源码入口及 README，并核对 Polygon 论文。

**建议：当前 6 组 12 SQL 不适合测组内排程收益；约束早构造也不宜作为独立新机制。先完成官方 bounded verifier 经统一前端、完整合同的正向适用性验证。如果要检验一个低资源系统组合，只有在相同公开来源组中先冻结至少 4 个唯一原 SQL 后，再测“选择一个查询对求合法反例、对整组执行该反例、按输出划分查询”的排程。它有可能节省端到端 CPU，但该收益尚未观察，也不是已确立的新颖性。**

## 1. 哪一个确有头部空间

| 候选 | 相对强简单对照剩下的区别 | 当前 6×2 的头部空间 | 结论 |
|---|---|---|---|
| 先构造满足 PK/FK 的数据库，再检查查询差异 | 若早检查对照使用相同变量顺序及同样的 PK/FK 可完成性传播，二者访问的合法前缀和合法叶可相同 | 可能只剩常数实现开销，未证明减少搜索 | 不选作本轮研究机制 |
| 选择组内查询对、求一个反例、向全组广播 | 给对照同样广播后，区别仅是选择下一个待区分的 pair | 每组只有一个 pair，选择空间是单元素，严格没有组内排程收益 | 当前数据结构不适用 |
| 扩组后的 pair 排程加共同广播 | 所选 pair 的模型可能顺带区分许多未解决 pair；或小 pair 公式比全组 OR 公式便宜 | 仅当同合同下有 ≥3 个查询才非退化；建议冻结到 4 个便于最小对照 | 可作系统组合 feasibility probe；不称新方法成立 |

这里“早检查已吸收”的断言是有条件的，不是声称任意 FK 推理都免费。对确定的构造器 C，如果它在前缀 s 上只做键一致性、外键已有目标／剩余目标槽可完成性、检查约束传播，令简单枚举器 E 采用同样变量序和同样传播，则 C 与 E 的转移关系可以相同。改变名称、只把无效状态从终点移到前缀、或与完全不检查约束的随机拒绝采样比，不能证明超出 E 的机制收益。

若 C 强制创建新父行而 E 允许复用已有父行，二者反而可能搜索不同空间；这种“少访问”可能来自漏掉合法模型，不能记为加速。复合键、同一行有多个 FK、nullable FK、字符串相等及多条唯一性约束都必须保留，不能以单键无 NULL 的简化替代完整合同。

## 3. 唯一建议保留的系统组合及精确不变量

适用于同一完整 schema／constraint／dialect／结果比较合同的原始查询组 G={q1,…,qk}。只复用确实在这个合同下合法的具体数据库，不跨合同传递反例。

维护已验证反例集合 V。对每条查询记录它在所有 D∈V 上的规范化结果序列。相同序列的查询构成当前 block；序列不同的查询对已被具体反例区分。求解器每次只接收同一个冻结行数界 b 和一个尚未区分的 pair，寻找 D⊨C 且 qi(D)≠qj(D)。模型经独立合法性与实际执行检查后，整组查询在 D 上各执行一次，再细分 block。

必须保持：

1. **证据不变量。** 每个标为 REFUTED 的 pair 必须绑定具体 D、完整 C 哈希、两条原 SQL 哈希及实际不同的规范化结果。solver 的 SAT 本身不是最终反例证书。
2. **组不变量。** block 只表达“在已见输入上未区分”；它不是等价类证明。两个 query 得到相同 ERROR 也不能作为相同结果；错误不得编码成普通输出值来制造或消除差异。
3. **单调证据。** 增加已验证 D 只能细分现有 block，不能撤销已经验证的反例。若撤销，必须报告语义／解码错误并停止该实验。
4. **域不变量。** 全部策略使用同一行数界、同一值域抽象与同一约束。只有对完整 bounded encoding 的 UNSAT 可称 BOUNDED_NO_COUNTEREXAMPLE；超时、unknown、固定 UA 的 UNSAT 或有限抽样无差异均不能这样解释。
5. **边界不变量。** b 内无反例始终不意味着无界等价。对某一 bound 证明的结论不能直接当作另一个 bound 的结论复用。
6. **资源不变量。** 解析、公式构造、solver、数据库解码、合同检查、全部 query 重放、选择器以及缓存建立时间全部计费；不能只比 solver 调用数。

一份 witness D 对当前 partition P 的真实额外收益可精确计算：

    gain(D) = ΣB∈P [ choose(|B|,2) − Σv choose(|{q∈B : q(D)=v}|,2) ]。

结果 v 必须按冻结的 bag/list、NULL、类型、数值精度及排序合同规范化。这个量统计新增的、经具体反例证明的不等价 pair，没有隐藏 gold，也不将同组 pair 当作独立统计单位。

允许某次 witness 只在被选 pair 上成功重放而其他 query 报错时记录局部反例，但不得记其全组 gain；所有方法采用相同规则。更干净的首轮探针应先通过组内所有查询的正向前端适用性门槛。

## 4. 一个可冻结的轻量排程假设，不能包装为新颖机制

在最大的未区分 block 内，尝试选择语法结构差异相对编码大小较大的 pair。它可能比盲选更快取得一次高 gain 的 witness，也可能专挑语法不同但语义等价的难 pair。没有单调改进或最优性保证。

若父任务需要一个确定候选，可仅使用统一 AST 已有信息：f(q) 为冻结算子类别计数向量，包含 join 模式、聚合函数、DISTINCT、GROUP BY、HAVING、子查询、NULL 判断和排序；L(q) 为 AST 节点数。对当前最大 block 内的未尝试 pair，按 ||f(qi)−f(qj)||1/(L(qi)+L(qj)) 降序，SQL 哈希打破平局。每个 pair/bound 最多调用一次；所有特征类别、顺序及平局规则在运行前固定，不根据结果调权。

这只是一个廉价搜索顺序假设，不能把 feature vector、pair selection 或共同广播当成已确立贡献。如果父任务已有另一确定候选，不应为挽救结果把二者择优汇报；冻结一个即可。

## 5. 最小可证伪对照

**先决条件：** 当前 k=2 每组只剩唯一 pair。相同 seed、bound、前端与 solver 下，所有组内选择策略产生同一请求。因此目前无需运行任何比较就能排除“组内排程优于独立 pair”的实验设计。跨组调度是另一任务，不在这里偷偷替换。

**若继续扩组：** 仅在已经允许暴露的六个公开来源组中，从原始 source_record 抽取 byte-identical 的原 SQL；去重只用于身份，不改 SQL。按事先固定、与结果无关的顺序取每组至多 4 条；保留当前两条并按 source line、pair position 追加。完整 schema/constraint 哈希必须相同，否则不能合组。先冻结清单，不读取 source 的 gold/result 字段；不打开 reserve。不足 4 条的组如实报告，不补造 SQL。

**建议对照：** 所有策略共享 verifier 版本、前端、完整合同、相同 witness validation 和全组广播。

- E：原 SQL 哈希次序独立 pair 求解，找到 witness 后立即全组广播；已区分 pair 跳过。
- R：一个预注册 seed 的随机 pair 顺序，完全相同广播；不得跑多 seed 后挑最好者。
- O：全组 OR，寻找 C(D)∧∨(i,j)∈U[qi(D)≠qj(D)]；公式共享每条 query 的编码，找到 witness 后同样广播。其 UNSAT 仅针对固定 b 与完整编码。
- H：上节唯一冻结的结构差异／大小排程。

本轮扩到多个正式 paper baseline 会超出自动推广技能 v1 的“一主基线”自动验证包。以上只能作为明确标记的 feasibility／系统组合诊断；不能把它直接记为 automatic promotion。Polygon 是必须核对的最强相邻工作，不能因为统一前端接入成本而在新颖性讨论中略去。

**可度量真实收益：** 固定端到端 CPU 总预算内，逐组报告经过重放的不同反例数、新增 refuted pair 数、首次有效反例时间、随 CPU 的累计 refuted-pair 曲线面积，以及每个 witness 的 gain 和代价。等预算主结果不能以“次数更少”代替真实 CPU。任务目标若包含合法小反例，还需逐表行数及总行数作为附指标，但不允许用缩减时间不计费来获利。

**最小停止判据：**

- 若扩组后仍全部 k=2，停止排程比较。
- 若 verifier／完整合同／重放前端未正向适用，不把 unsupported 当作候选的收益；先记录应用边界。
- 若固定 E 或 R 已达到 H 的 refuted-pair/CPU 前沿，或 O 在相同预算支配 H，拒绝 H 的本轮 headroom 假设，不调 feature/seed。
- 若全部方法都零合法反例，结论只能是本预算缺少正向证据，不能说 query 等价或方法同样好；不扩大 bound 来追求成功。
- 只运行单 worker、父任务批准的既有小预算，不因本文提出方案启动 solver。本作者没有执行该探针。

仅六个来源组足以迅速杀死没有头部空间的组合，不足以建立推广性、统计显著优势或投稿成熟度。组内 pair 有强相关，不能把 6 组扩成几十个 pair 后冒充独立样本增多。

## 6. 更立即、可执行的下一步

优先对这 12 条原 SQL 做官方 bounded verifier 的同前端正向适用性：冻结官方版本、本地补丁清单、原 SQL／完整合同哈希、row bound、超时、字符串解码和输出比较合同。每组只走一次官方入口链：建立 schema → add_constraints → 原 SQL 分析 → bounded 结果；保留 unsupported／unknown／timeout 为独立状态。任何 SAT 模型都走统一完整约束检查与实际 SQL 重放。

本地官方入口 __main__.py 使用 env.add_constraints、save_checkpoints、env.analyze；environment.py 的 analyze 路径最终调用 solver.check。因此不能把调用 analyze 描述成无 solver 的静态检查。本文仅阅读源码，没有调用它。

当前最大的可验证问题是：完整 PK/FK、字符串及聚合/NULL/分组合同是否能通过同一条工具链产生一个可重放的合法反例，或者清楚返回 bounded/unsupported 状态。如果这一环还未正向通过，新增排程只会把前端错误或不支持情况重新排序。

## 7. 先例与最终边界

[Polygon 论文](https://arxiv.org/html/2504.06542) 已把多 SQL 的输出关系作为输入生成目标，并研究 query disambiguation；其共享输入、多查询约束与反例区分用途不能作为本轮新颖性。本文提出的 pair 排程只是依赖现有有界求解器的系统组合。

[VeriEQL 官方仓库](https://github.com/VeriEQL/VeriEQL) 提供带完整性约束的 bounded verifier 及反例检查工具。论文性能数字不替代当前固定版本、前端与合同的实测适用性。

结论：在现有六组两查询结构上，不存在可测的组内排程头部空间；对强早检查 baseline，约束早构造的独立机制空间尚未出现。若必须二选一投入一个极小后续探针，选择**先冻结公开原查询扩组，再做共同广播下的排程对照**；前提是官方工具链先通过正向适用性。当前仍为 HOLD_NO_VALIDATED_SYSTEM_GAIN，不声称找到了新的研究贡献。
