# H12 手工控制记录

日期 2026-10-11；作者构造和手推，NOT_EXECUTED。以下 4 个控制与六环主反例不是自然数据，不构成性能 benchmark。不以控制通过率支持任何效果声称。

## HC1：交换对称不能误报不等价

B=R(x,y)∧R(y,x)，H=∅，M={x}，N={y}，R 的 PK 为满元组。交换 x、y 是 body 自同构，因此对任意 R，合法 x 值集合与合法 y 值集合就是同一集合；两查询恒等价。

canonical 二环为 {(x,y),(y,x)}，重数 2/2。C=∅、S={x,y} 的 lift 是两个不交二环，完整赋值 4，重数 4/4。C={x}、S={y} 时 R={(x,y0),(y0,x),(x,y1),(y1,x)}，完整赋值为 (x,y0),(y0,x),(x,y1),(y1,x)，共 4 种；投影重数却为 3/3。C={y} 对称。C=V 无组件。此控制展示 self-join 会引入 canonical 身份赋值之外的赋值，不能套用“全库只有两种满足赋值”。

## HC2：满元组 PK 三角可区分，三行最小

B=R(x,y)∧R(y,z)∧R(z,x)，H=∅，M={x}，N={x,y}。R 的 PK 为满元组。canonical 有向三环 {(x,y),(y,z),(z,x)} 只有三个旋转，重数 3/3，不是区分库。

C={x}、S={y,z} 是合法闭集—组件；其 lift 为 {(x,y0),(y0,z0),(z0,x),(x,y1),(y1,z1),(z1,x)}。全部完整赋值是两组三环各自的三个旋转，总共 6 种；x 的值域为 {x,y0,z0,y1,z1}，而 (x,y) 的投影就是六条边，重数 **5/6**。因此该三角不能反驳完整 lift 家族。

更小的合法区分库是 R={(a,a),(a,b),(b,a)}，a≠b。全部三角赋值为 (a,a,a),(a,a,b),(a,b,a),(b,a,a)。x 投影={a,b}，(x,y) 投影={(a,a),(a,b),(b,a)}，重数 **2/3**。

三行的最小性仅针对这一查询对。证明：M 投影总是 N 投影的满射；若两数不同，必有某个 x 在满足三角的投影中连到两个不同的 y，故至少两条行有同一个第一列 x。如果整个 R 最多两行，则所有行的第一列都为 x。在三角路径 x→y→z→x 中，每个后续起点也只能是 x，于是唯一可能是 loop (x,x,x)；这与两个不同 y 矛盾。因此 ≤2 行不可能区分，所列 3 行确为最小。

## HC3：单列 PK 三角恒等价

与 HC2 相同 B、H、M、N，但 PK 改为 R 的第 1 列。每个合法 x 最多决定唯一 y，继而唯一 z；所以满足赋值投影 (x,y)→x 是双射，查询对在所有合法库上恒等价。FD 闭包 cl({x})={x,y,z}；闭集只有 ∅ 与 V。

HC2 的 3 行库同时含 (a,a),(a,b)，违反新 PK；HC2 的 6 行 lift 固定 x 却变动其后继，同样不合法，且其 C={x} 已不闭合。不能把这些实例拿来宣称单列 key 下仍不等价。合法 canonical 三环和两个不交三环分别给 3/3、6/6。

## HC4：共享隐藏 parent、non-anchorable 的两赋值边界

关系 P(p)，PK=p；C(c,p,x)，PK=c；D(d,p,y)，PK=d；E(e,p,x)，PK=e。C.p、D.p、E.p 均 FK→P.p。B=P(p)∧C(c,p,x)∧D(d,p,y)∧E(e,p,x)，H=∅，M={x,y}，N={x}。

M、N 的 FD 闭包分别仍为 {x,y} 和 {x}，均无法锚定隐藏 key 或 parent；x、y 只在相应非 key 位置出现。完整 FK 目标 P(p) 已在 body 中。

取 C_fixed=cl({x})={x}，组件 S={p,c,d,e,y}；两个完整赋值生成：

| 表 | 两行 |
|---|---|
| P | (11), (12) |
| C | (21,11,7), (22,12,7) |
| D | (31,11,8), (32,12,9) |
| E | (41,11,7), (42,12,7) |

每表 key 唯一，所有 FK parent 存在；共享 x=7 在两个 parent group 中保留。parent join 强制 C、D、E 属于同一组，只有两种满足赋值。M 投影={(7,8),(7,9)}，N 投影={7}，所以 **2/1**。冻结 d 却改变 y 会破 D 的 PK；同时也把 x 变成不同值则两查询变成 2/2。该构造正是已有 FD closure + Armstrong 两元组模式的直接应用，不是本轮新 primitive。

主反例也使用复合 PK（R 的两列），所以否证并未靠排除复合 key。四个控制的目的分别是防止对称误报、避免把三角误认反例、检查 FD 法律边界，以及保留 non-anchorable 共享碰撞能力。
