# CaliberGraph 第三轮：有界真实问题诊断

日期：2026-10-11。结论：**STOP_RESEARCH_PROBLEM_NOT_ESTABLISHED**。前两轮被否定的机制保持停止。本轮没有建立可进入新机制研究的稳定真实求解瓶颈，不提出第三个机制，不扩大队列，不修改原稿，不投稿。

这是一次不完整但保留全部分母的诊断。完成的 10 次原查询对求解均低于预注册 250ms CPU 阈值；另外的支持域、合同、比较路径与监控问题不能充当求解瓶颈。后段因监控故障中止，不能据此断言剩余组或全部公共查询都容易。

## 来源与预注册

固定三个公开文件共 24,455 对、48,910 个查询槽位：Calcite 397 对、Literature 64 对、LeetCode 23,994 对。本轮核对全部字节身份及逐行清单；只从 LeetCode 原 `file` 标签选主开发组。Calcite 缺规则／测试族来源映射，Literature 是经改写的文献控制，均不用于补足自然来源组数量。

LeetCode 按 8 个有优先级的互斥词法候选分层，每层最多 4 个不同来源标签；组内取预先规定的 token 复杂度下中位代表，使用固定种子排序，跨层和完全相同 SQL 去重。规则未使用求解结果。排除旧 6 个开发组和 4 个已知保留组；保留组仅在源文件流中读取 SQL 前的 metadata 以排除，不解码其 SQL，不打开 reserve 文件。

最终登记 **21 个不同来源标签组、21 对、42 个不同原 SQL 哈希**。不同标签不证明语义或统计独立。S1 集合操作、S2 派生表聚合、S3 子查询／相关提示、S4 外连接、S5 自连接／重复关系各 4 组；S6 三表关系候选 1 组；S7、S8 为 0。缺口 11 不补样。分层是词法近似，不是已认证语义类别。

完整库存保留 16 条词法失败：7 条括号失败，9 条不支持字符；未修复后重新筛选。其余排除项、达上限未选项和跨层去重均在账本中。详见 [来源选样摘要](analyses/source_selection_summary.zh.md) 与 [扫描报告](runs/source_inventory_01/report.json)。

21 组中 20 组有非空约束 JSON，1 组为 `null`（dev03_20，因批次中停最终未启动）。`null` 不补成空 C。逐约束的原题／DDL 映射、答案接受状态及上游配对构造过程均未确证；全部 21 组的真实业务合同真值与完整性仍未验证。公开基准 pair 不是天然缺陷 gold。详见 [来源合同审计](audits/source_contract_provenance.zh.md)。

这批数据此前已被公共适用性扫描曝光，本轮也用于开发诊断；它不是新的 finaltest。旧反复使用的开发组未包装为独立测试。

## 执行范围与透明修订

共用冻结的官方 VeriEQL 前端和运行时，原始 SQL、全部 schema、全部 C 原样输入，不删字段或约束。未知类型或约束必须拒绝，不能借官方静默忽略而声称支持。采用**每个物理表恰好 2 条存活行**；这不是至多两行，也不是无界等价检查。

原方案为每组累计 solver wall 目标不超过 2 秒，每次合同检查最多 100ms、查询检查最多 800ms；只有首个 query CPU 达到 250ms 或返回 unknown 才进入第二个独立 Environment 重编码。稳定成本要求两次已知一致 verdict、两次均过阈值且成本比不超过 2，并另需完整语义准入证据。没有任何组被伪造语义准入标记。

机器门槛为一分钟负载不超过 4、可用内存比例至少 25%；单 worker、nice15、CPU 4 秒／wall 5 秒、外部 RSS 采样 256MiB。Darwin RSS、wall 与 solver 轮询不是精确硬分配或硬时钟保证，真实超限／删失必须保留。

首批资源门通过（load 2.395、可用比例 34%），但 fork 后的 preexec 设置 RSS 限制失败，没有执行 worker 解释器、SQL 或 solver。标准库逐步自诊断确认 nice、CPU、core 设置成功，只有 `RLIMIT_RSS` 抛错。**不能称从未创建子进程；该失败子进程费用已计入。**

原“一批不重启”预承诺被明确、前瞻地修订一次：[启动恢复修订](decisions/bootstrap_amendment_01.json)。独立审查接受在零科学输出条件下，只移除不可用的 advisory RSS 调用，保留外部监控；样本、顺序、科学代码与阈值不变。原失败记录和冻结 v1 完整保留。恢复前累计成本为 7.876722 秒，即已含扫描的首批保守费用 6.876722 秒，加 1 秒诊断／尾部储备，没有重复计算扫描。1 秒是预留而非实测。

恢复批次开始实际执行，随后在第 18 组导入阶段遇到 `ps` 的 50ms 监控超时。监督器只终止并回收了自己的 worker，停止余项。**没有第三次恢复、补跑或放宽门槛。**这次中止是监控失败，不是 solver timeout，也不能解释为 unrelated_project 已超载。

## 全部结果分母

21 个登记组 = 17 个返回 + 1 个导入阶段监控中止 + 3 个未启动。32 是容量上限，未登记的 11 个槽位不进入结果分母。此前还有一次未执行 worker 的 bootstrap 失败，独立计入执行史。

| 观测类别 | 组数 | 证据边界 |
|---|---:|---|
| 原查询比较返回且 query CPU <250ms | 10 | 仅本引擎、恰好两行设置下的快速检查 |
| Schema 不支持 | 4 | 3 个 ENUM schema、1 个 TIME schema；原样拒绝，无类型修补 |
| 完整官方 C 在恰好两行下 UNSAT | 1 | 查询未运行，不是查询等价证据 |
| 官方比较中的非 SMT 提前异常 | 1 | raw INCONCLUSIVE；没有 query check，也没有 SAT 反例 |
| 官方 parser 拒绝 | 1 | raw INCONCLUSIVE；据具体失败阶段归因前端解析 |
| 导入时监控中止 | 1 | 0 solver checks，强制回收有收据 |
| 尚未启动 | 3 | 保留 NOT_RUN，不推断支持或速度 |

原始分类中的 2 个 INCONCLUSIVE 没有被重写。诊断解释如下：

- dev03_04 在官方 verifier 的输出属性 UF 标记不匹配分支抛 `NotEquivalenceError`，位于查询 SMT 检查之前。异常文字不是已验证反例，也没有证据据此宣称前端 bug。
- dev03_17 第二条原 SQL 的 `ParserSyntaxError` 保留；该组没进入查询求解。连同 4 个 schema 拒绝，得到 5 个已定位的前端／表示支持边界。
- dev03_02 同时具有官方 strict self-FK 和全列笛卡尔 `neq`：任一 referee 必须等于某个 ID，又必须不同于所有 ID，非空表下冲突。实测是两行 UNSAT；上述更一般冲突来自对官方操作语义的静态推导。它不证明原题业务合同错误，更不是科学方法收益。

总计执行 **13 次完整 C 非空检查、10 次查询检查**。10 次 query 为 1 个原始 SAT、9 个固定形状 UNSAT；query CPU 范围 **7.908–60.638ms**，中位 **21.192ms**，合计 **261.677ms**。所有 23 次 solver check 合计 CPU **319.461ms**、wall **320.043ms**。最大单组累计 solver wall **65.721ms**。没有 query unknown／timeout，没有触发独立重复成本测量，也没有稳定成本候选。

唯一 SAT 已核模型满足全部提交的官方建库／C facts 与实际比较 assertions，并导出完整物理模型。没有通用独立具体 C checker、真实 DBMS 回放或字符串／方言忠实性认证，因此不称自然业务缺陷。9 个 UNSAT 也不称无界等价。

恢复批次自身及监控 CPU 为 16.718492 秒；加此前成本与末尾 0.1 秒储备，受控扫描／实验保守总记账为 **24.695214 秒**，低于 120 秒。worker 峰值 RSS 为 **118,259,712 bytes**（约 112.78MiB），记录中没有 CPU、RSS、wall 或 solver 超限。监控超时本身完整保留，不能因 `violations=[]` 隐去。详见 [成本及分母复计](analyses/execution_recount.json) 与 [批次收据](runs/batch_02/batch_receipt.json)。

## 研究判断与停止

这轮已观察到的问题主要是类型／解析支持、官方合同解释、非 SMT 比较路径，以及本轮监督器的运行限制。它们没有建立新方法要解决的稳定求解成本问题。已执行的查询比较虽快，但样本少、固定两行、来源真实性未闭环，且后段被监控中止，不能推广为“自然 JOIN 没有难例”。

结论因此是“**现有有界证据不足以建立研究问题，停止**”，而不是“已证明该问题不存在”。不以必须超过 baseline 为理由补样、筛结果、造缺陷或继续机制搜索。旧两轮机制继续否定；本轮不晋升机会、不提出新机制、不进入最终测试。

独立终审与作者写作分开。终审身份、结果及作者接纳记录在最终交接清单中绑定；独审不重新运行 SQL／solver。旧两轮冻结证据核对与存储状态另记：本地保存，未做外部备份；DataHub 写入受当前新目录边界限制，未注册。原稿、旧冻结、保留文件未修改，未读取凭据、未购买资源、未更改系统安全或操作 unrelated_project 进程。
