## 手推实例与完整 C

**A — 成立，概率范围明确。** `P={(1,0),(2,0)}` 的两个 key 唯一，所有值非 NULL，无 FK。第一查询为 `H=(v), M=∅, E={k}`；第二为 `H=(v), M={k}`，故都属于 C。输出分别是 `[0]`、`[0,0]`。固定两个不同 key、两个 v 独立均匀采样时，恰有 q 个相等的有序值对，共 q² 个，成功概率为 `1/q`。此概率不覆盖相关采样、小域偏置、直接类型抽样或 pair-driven 生成器。

【判断】这是对朴素 IID 数据生成器的否证，不是 PIT 定理失效。若 q 是素数幂并在 F_q 上写 `1-(a-b)^(q-1)`，次数为 q−1；Schwartz–Zippel 给出的非零概率下界仍为 `1/q`，恰好很弱而非数学意义上完全无信息。固定不同 key 的抽样无需也不应让 PK 值随机碰撞。

**B — 成立，但不新。** 两个 Customer key 为 1、2；两个 Orders key 为 11、22；每个 `cid` 都有父行，FK 图只有 Orders→Customer。常量头 1 下第一查询 `M={c}, E={o}`，第二查询 `M=∅, E={o,c}`。可扩展的 c 取值集合是 `{1,2}`，所以多重度为 2、1。

【证据·解析核对】c 在 Customer 的 key 位置，同时在 Orders 非 key 位置；静态锚定集合为空。唯一非平凡 FD 为 `o→c`，空输出闭包不能决定 c。因此 c 无法 demote，查询不可锚定。把 o 固定为 ô、让 c 取 c₁、c₂，产生 `Orders(ô,c₁),Orders(ô,c₂)`，违反 PK，而 FK 仍满足。用不同 o 修复这个实例，不蕴涵对任意查询保持分离。

【判断】“给每个 child 新 parent”也不是一般修复：一个 parent 配两个不同 oid 的实例，使 distinct cid 数为 1、订单数为 2；改成两个 parent 后两数均为 2。这里关键是保留有用的相等结构，而不是仅有 fresh keys。

**C — 计数反例成立，需明确观察器层。** SQL 中复用合法 WitnessP；不是主文叙述的 unary R，但同样有两行。严格落在 C 的底层查询可写成 `SELECT 1 FROM WitnessP` 与 `SELECT 1 FROM WitnessP a CROSS JOIN WitnessP b`，常量 1 的多重度为 2、4。所附 COUNT 只是观察这两个多重度；不能据此扩充 C 为任意聚合语言。两数模 2 都为 0，但查询仍在自然数 SQL 语义下不等价。`n^p−n` 在 F_p 恒零的陈述正确；它否定不控制次数/特征的 fingerprint，不否定所有选素数方案。

【判断】在合法行指示量的 Boolean 采样中，`∏x_i` 仅在全 1 点非零，独立公平位下成功率 `2^-k`。这与 field-size 无关；若还要条件化到 PK/FK 可行子集，概率必须重新推导。DISTINCT 的自然数零/非零测试也不能无证明地改成模 p 的零/非零测试。

【证据·解析推导】U-semiring §3.1 的 squash 公理 `squash(0)=0`、`squash(1+x)=1` 也不能原封不动放入非平凡有限域：取 `x=-1` 即矛盾。因此有限域化不是只把已有 U-semiring 的底层数域替换一下；它需要另行证明适用片段和 lift。这里没有声称作者已经进行了这种错误替换。

## FK 分支警告与知识状态

【证据·解析核对】主文件第 13 行的二叉 FK chase 警告成立：第 i 层新原子数为 `2^i`，深度 d 的完整树总原子数为 `2^(d+1)−1`。每个新 key 是上层不同 fresh 变量；不存在必须由 key 合并的分支。这证明 ordinary fresh-witness chase 的显式大小不能仅用“初始原子数×链深度”控制。
