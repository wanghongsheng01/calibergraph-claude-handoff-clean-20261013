# 第四轮：最小行数边界的开发诊断预注册

角色：作者侧问题证据，不是新方法实验，也不是最终测试。原始来源为第三轮已曝光的 `dev03_18`（LeetCode 596.csv，冻结 JSONL 第 2924 行）；读取该组完整原始 SQL/schema/C，不改写查询，不添补业务约束，不采样新标签。

## 为什么继续

第三轮 exact2 上十次查询检查很快，仅说明当时准入且完成的查询/合同/行数。它既没有覆盖 COUNT≥5 所需的行数，也没有覆盖不同表不等基数；部分合同在统一等基数下甚至强制双射。当前来源还集中于少量公开查询组，缺少业务合同真值。不能从这些结果推成全 SQL 无瓶颈，或把这一限制本身叫创新。

文献门禁已排除普通增量 bound、异构基数搜索、已知 PK/FK 基数传播、合同蕴含选路、相同元组带权压缩和已知 NULL/COUNT 造数作为独立贡献。一般 key-erased lifting 与聚合条件推导仍在审查中，未晋升为新机制。

## 唯一运行问题与预测

H-P（问题证据，非新颖性假说）：完整显式 C 仅给 STUDENT 主键；CLASS 可空。固定的原始 pair 在少于五行时无输出差异，但在五个不同非空 STUDENT、CLASS 全 NULL 时产生差异；将同一五行 CLASS 改为一个非空常量则差异消失。

预测来自 COUNT 门槛和普通 SQL NULL 比较的静态推导，未使用本次执行输出。少于五行不能产生任一查询的合格组；五行 NULL 组使第一条返回 NULL，第二条的相关等值选择无匹配，计数为零。该命题不认证原题业务是否允许 NULL，也不声称自然缺陷。

完整固定分母为十个 slot：N=1..5，每个 N 顺序执行 concrete、official；每个只执行一次。concrete 同时回放全 NULL 与非空同组对照。official 不加任何 fixture 约束，完整编码原 C/SQL，冷启动一次 Environment。官方冻结代码本身把每个基表 slot 固定存活，所以本轮是 exact N，不是 ≤N；不删除该事实来迎合论文描述。

## 对照、成本和解释

官方原始完整 C 冷编码为执行基线。SQLite + 独立主键验证是具体语义对照，不能当同一性能竞赛，也不能声称复现 XData。非空 CLASS 是唯一消融；相同 N、相同 STUDENT、相同查询字节和 C。

保存每次 C/query solver 调用、UNKNOWN/错误/资源中止、AST、公式、完整模型以及具体 DBMS 的袋输出。分别计前端/编码/check/验证/导入、worker wait4、所有监控子进程及父进程成本；嵌套阶段不重复相加。solver 官方 SAT 仅是编码反例，SQLite 手工机制实例不是该 SAT 模型的回放。

预算：实验执行阶段父进程与所有已回收子进程合计最多 60 CPU 秒；预先计入 1.0 秒启动核查储备及 0.2 秒收尾储备。文献搜索与作者文件编辑不冒充被该预算覆盖。单 worker、nice≥15、3 秒硬 CPU、4 秒 wall；RSS 外部采样上限 256 MiB。每 slot 前 load1≤4、memory_pressure 可用≥25%；监控失败立即停后续，绝不触碰 unrelated_project 进程。C check≤100ms、query check≤700ms，累计 solver wall 上限 2 秒，外部 1.5 秒停止阈值。不存在额外重复、扩大 bound、自动修 parser 或结果后重排。

## 判据

- 任何输入/源文件/运行时哈希不符：不得执行。
- 任一机器门禁、监控、批预算失败：立即保留余下 NOT_RUN，不自动重试。
- SQLite 与静态预测不符：否定 H-P，先定位语义边界，不通过换 query/C 修正胜负。
- 官方前端拒绝：仅报告前端覆盖边界，不能当 SMT 成本或方法收益。
- 所有官方 N 都快：没有证实求解成本瓶颈；不得为造优势放大常数。
- 更高 N 的耗时或 UNKNOWN：只记单次开发成本信号，不宣称普遍复杂度或稳定优势。
- N=5 的预测成立：只确立原 pair 的条件化边界与 exact2 的局限；不能使已被先例覆盖的机制重新变新。
