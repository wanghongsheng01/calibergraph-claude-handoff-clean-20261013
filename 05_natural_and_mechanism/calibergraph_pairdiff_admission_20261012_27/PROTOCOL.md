## AST and algebra rules (conservative, source-preserving)

Use pinned local sqlglot 23.12.1 only to parse, never execute SQL or import Polygon/SMT. Bind table aliases to occurrence positions and actual full schema column identities, preserving projection positions, relation occurrences, predicates, literal types, and bag multiplicity. Do not perform predicate implication, constant folding, join reordering, redundant join removal, or infer integrity constraints. Unsupported/ambiguous name resolution or typing is a refusal. Case normalization is only identifier normalization under the declared source dialect; quoted identifiers/literals retain exact value. No output names are used as values.

The admitted complete-query fragment is deterministic, total SPJU bag algebra: scans; inner/cross joins with explicit conditions; selections; positional simple-column/literal projections; UNION ALL of compatible outputs. Projected arithmetic/functions/casts and correlated subqueries/CTEs are refused in v1. Selection expressions admit resolved columns/literals, comparisons, IS NULL/NOT NULL, AND/OR/NOT and IN literal lists; unknown functions, arithmetic, coercion-sensitive rewrites and subquery predicates are refused. Schema/output compatibility must be checked or the pair remains unadmitted.

DISTINCT, UNION distinct, INTERSECT/EXCEPT, aggregation/GROUP/HAVING/window, outer/semi/anti/natural/USING join, ORDER/LIMIT/OFFSET, volatile/unknown function, CTE/correlation and unsupported syntax are barriers. V1 conservatively refuses the whole query containing a barrier; local subtrees behind a barrier may be counted as descriptive sharing only, never eligible removal or lifted difference. Refusal of this fragment is not proof that a richer correct compiler cannot exist.

For signed multiplicities Δ(A,B)=A−B, permit only:

* E: exact bound relational subtree Δ(A,A)=0. Identical whole pairs are trivial cache controls, not mechanism candidates.
* U: flatten UNION ALL preserving a multiset of branch occurrences; cancel matching branches one occurrence at a time. (A+A+B)−(A+C) retains one A. Union type/output alignment must hold. Cancellation cannot drop a table or C clause from the legal input domain.
* S/P: Δ(σ_p A,σ_p B)=σ_p Δ(A,B), and Δ(π_e A,π_e B)=π_e Δ(A,B), with exact predicates/projections and aligned input columns. They share a linear context; they do not by themselves erase a nonzero child or prove EQ.
* J: for identical join condition/output order and aligned operand schemas, Δ(A⋈B,A'⋈B')=(Δ(A,A')⋈B)+(A'⋈Δ(B,B')). If a delta is zero, eliminate that product, but retain the common other operand in the remaining product. No division/cancellation of a common join factor, no injectivity assumption. Signed intermediate multiplicities are not negative rows in the concrete input database. General differing-both-sides expansion is recorded as an identity opportunity only and not credited as savings unless the exact zero rule fires.
* Optional descriptive S-different identity on an identical input: σ_p A−σ_q A equals the signed exclusive-TRUE regions. SQL UNKNOWN requires IS NOT TRUE, not ordinary NOT. V1 records this only, does not implement predicate construction or count it as strict elimination.

Residual relational-DAG size counts unique scans, projections, selections, joins, unions and explicit difference/negation nodes; integer coefficients/sign edges are recorded. Compare with the original two-query **shared DAG**, not duplicated syntax trees. Common scans/factors needed by nonzero residuals remain. Full-schema/IC costs remain outside both query-DAG counts. Metrics are static proxies, not symbolic-table, UA-label, SMT-size or runtime measurements. Record ordinary same-projection/filter contexts separately from genuine zero-term/branch removal.

## Label-free IDs, statistics and gate

Scan all records in source order. Stable ID is dataset + original source key/index + line number + SQL/context digest. Freeze all IDs and reasons, including parse errors, exposure exclusions, barriers, ambiguous schema, equal pairs and no strict reduction. Count unique unordered pairs per complete supplied context. LeetCode problem source file and ParSEval dbid provide source-family diversity; these are not production versions. Representatives: ascending SHA256 of stable ID within each structural category, at most 3/category, never chosen by baseline performance.

Report original denominator, prior-developed exclusion count, parse success/failure, barrier/refusal counts (multi-label plus exclusive primary reason), admitted SPJU pairs, exact-equal controls, UNION cancellation cases, matched S/P contexts, exact JOIN zero-term opportunities, descriptive shared input/filter changes, common DAG node-size distribution, and residual vs shared-DAG reductions with all identities. Do not claim every syntactic opportunity yields solver gain.

**Narrow-prototype gate fixed now:** at least 20 distinct, nontrivial, not-identified-as-developed natural pairs across at least 3 source families, each with at least 2 fewer unique relational nodes and at least 20% reduction against the shared-DAG baseline, caused by U cancellation or J zero-term elimination propagated through S/P. Ordinary exact-pair memoization or common-subexpression sharing alone cannot qualify. If below either count/diversity threshold, reject this candidate for this available workload and stop; do not synthesize replacements, expand the fragment, fetch another dataset, or tune thresholds after inspection. Passing would justify only a small prototype proposal, not a new-method or performance claim.
