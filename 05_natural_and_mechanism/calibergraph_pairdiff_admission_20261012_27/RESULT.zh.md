## 共享规模及原 SQL

仅看非平凡准入对，ParSEval 的公共 DAG 节点数 min/median/p90/max 为 **1/2/3/7**，LeetCode 为 **1/1/1/2**。ParSEval 原始共享 DAG 节点中位数 8，形式残差 DAG 中位数 9；LeetCode 均为 5。ParSEval 最大净缩减仅 12.5%，LeetCode 为 0。这里计入显式 difference 节点，因而可以出现负缩减；它不是 SMT 规模或运行时间的估计，不支持“方法已跑输”的说法。

哈希排序抽取的 12 个类别代表已保存完整、未经改写的两侧 SQL 与源文件行号，见 [REPRESENTATIVES.md](REPRESENTATIVES.md)。例如：

* BIRD `codebase_community/575`（源行 576）在 `users JOIN badges` 与 `badges JOIN users` 间变换连接顺序。v1 不做 join 重排，属于有自然 JOIN、无可按固定规则消去的零项。
* BIRD `formula_1/875`（源行 876）两侧同投影、同 `raceId=901` 过滤，但 join 等式操作数方向不同。固定规则未做等式交换规范化，只记录 S/P 上下文；DAG 8→7，不能算新颖机制成功。更强普通规范化可能将它归入完整相同对，这仍是缓存/重写控制。

## 曝露边界与拒绝理由

这些公开来源曾经历全库静态扫描，不能声称从未见过，更不能称为新的独立最终测试。本轮先冻结 127 个旧输入工件提取的 132 个 SQL 哈希，并排除十个已开发 BIRD case。LeetCode 的 10,558 是**保守的 SQL 重合排除数，不是声称过去实际开发过 10,558 对**：其中 10,557 条左 SQL 命中旧工件、27 条右 SQL 命中，存在交集。这种排除可能低估未开发的新 pair 可用量；结论不外推到被排除部分。未访问 protected/reserve_private。

v1 仅解析并绑定保守的 SPJU 结构，整个查询含屏障即拒绝，不跨 DISTINCT、聚合、outer join、order/limit 推差分。BETWEEN、LIKE、投影函数/算术、未解析名称和其他未覆盖构造均保留拒绝理由；没有为了增加样本放宽。名字绑定按来源方言/供应 schema 的标识符规则处理；这个扫描器不是一个已验证的通用 SQL 编译器，也没有证明数据库引擎和所有类型/排序规则的跨工具一致性。

原始日志有 11 项标作 SCANNER_ERROR；复核全部为 sqlglot TokenError，已在 [DERIVED_DETAIL.json](DERIVED_DETAIL.json) 明示重分类为分词失败，未修复 SQL、重跑筛选或改变原始记录。另有 95 个 ParseError。原始失败、未知、屏障和排除项都在总分母中。
