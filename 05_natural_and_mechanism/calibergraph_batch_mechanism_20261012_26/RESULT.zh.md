## 只审了一个机制

候选：先认证一整个参数化数据库区域都满足原完整约束、类型和固定查询分支，再把若干聚合查询对的输出差表示成精确多项式，选择一个使全部差非零的参数点，共同构造一个反例数据库。

它有明确的安全边界：区域必须是经认证的合法笛卡尔网格；每维取值数须超过对应残差次数之和；袋重复、NULL、行存在、溢出及完整 IC 都不能省略。逐坐标排除有限坏点的构造可成立，但它是基础多项式非零点论证。区域局部相等不能成为全域 EQ，联合目标 UNSAT 也不能成为各查询对 EQ。合法域为 x∈{0,1}、残差分别为 x 与 x−1 时，每对各自有反例，却不存在共同反例。

作者拒绝新颖性声明的理由是：

1. 多查询联合输出条件本身已有直接先例。[Polygon 的问题定义](https://arxiv.org/html/2504.06542) 接受 n 条查询及输出上的任意 SMT 条件。
2. 作者原先把同区域随机生成的保证说得过强，独审已指出这一点。均匀抽样在每维宽度 L≥2Σdegree(P_i) 的足够大合法网格上有常数成功概率；这不适用于任意满足逐维确定性条件的同一网格。例：X={0,1}^d、P_i=x_i，确定性逐坐标可保证成功，随机整点一次成功率却为 2^-d，完整 C 还可能禁止扩大网格。必须保留这个确定性与随机算法的理论区别；不能以“随机等价”普遍淘汰本候选。
3. 最有难度的部分是低成本生成足够大的完整约束合法区域；本轮没有提供超越已有方法的新区域构造。不能把这个缺失步骤藏在一个免费 oracle 中。

当前仍没有证据把基础选点论证提升为新的 SQL 方法，也未证明其优于 Polygon 联合目标及其他强控制。但这与上述有效的确定性区别是两个问题。最终拒绝依据是尚未建立非平凡的新增机制差异及有效区域构造，而非随机支配或 Polygon 可表达性直接推出算法无价值。完整算法、条件、转移方向和失效清单见 [冻结作者设计](design/ONE_CANDIDATE_AND_REJECTION.md)；其中“随机有同样保证”的宽泛措辞须以上述更正及 [独立挑战](review/INDEPENDENT_CHALLENGE.md) 为准。

## 强基线和最小可证伪标准

先例核读确认已有 schema checkpoint、编码缓存、多查询目标、跨候选测试集复用与逻辑蕴含缓存。查阅缺失仅限已列出的文件，不能推成全领域不存在。8 份源码均匹配锁定的官方文件身份，详见 [先例证据矩阵](prior/BATCH_REUSE_KILL_CHECK.md)。

任何未来重开都须把以下能力交给同信息、同语义、同资源的基线：持久 worker、AST/精确重复缓存、共享 C 与增量求解、带依赖检查的结果/蕴含复用、所有历史合法见证对待审查询的公平重放、query-specific test suites、Polygon 联合目标，以及同认证区域的随机生成隔离对照。

仅当自然批次经精确去重和历史见证重放后，仍有多个待审义务共享足够大的合法区域，且省下的剩余工作严格超过区域发现/认证、多项式构造、生成、完整验证、原 SQL 重放及失败回退总成本，才有可检验收益。若提升被普通缓存、测试覆盖、联合 SMT 或随机合法网格解释，停止当前候选。至少报告原始对数、唯一对/SQL、合法上下文数、准入/拒绝/超时/未知分母及完整成本。分组不能随机拆开同源重复参考 SQL，再把两侧称为独立开发与测试。

这些是未执行的重开条件，不是已冻结的新基准运行，也没有宣称随机控制已经实测。独审明确指出其尚不是可执行 preregistration：未来需先固定准入判定、独立批次选择、主指标、资源及尝试上限、随机种子/次数和最小有意义收益。目前不升级为 KEEP_FOR_TEST。增量和重放成本可耦合，最终应直接比较整个批次的匹配成本，不能任意相加逐查询费用制造节省。

## 旧成本只限定当前证据

8 个已暴露的 N≤1 Polygon 槽位总墙钟 4.860540 秒：schema/C 构建加编码 0.076073 秒（1.565%），导入加解析约 58.92%。其中 4 个 precise 槽位总墙钟 1.765915 秒，solver 调用 0.038520 秒（2.181%）；UA 的对应比例约 34.17%。search 包含 solver，二者不可相加。

这些数字不能推出新批次的加速上限，不能成为因果消融，也不代表全部约束求解成本。它们只说明，当前保存证据不支持用初始化开销或较弱 UA 对照来许诺科学收益。见 [原始静态成本表](SAVED_COST_INVENTORY.json) 和 [分模式表](SAVED_COST_BY_MODE.json)。
