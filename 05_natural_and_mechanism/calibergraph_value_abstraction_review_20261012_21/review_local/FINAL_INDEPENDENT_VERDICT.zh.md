## §5 固定 N 的手工构造核查：可保留

在稿件声明的 `1≤N≤2^63−1`、原 #1172 SQL/DDL、标准 SQLite 快照条件下，未发现反例。理由如下：

- 原 Patient.ID 为整数主键。k≤N 个父键单射到 1…k 均在 SQLite 有符号 64 位整数范围内，因此父 PK/NN 保持。每个非空子键依据原合法 FK 的父行重命名，保留两个 FK；Examination 可空子键保持 NULL。
- l≤N 条 Lab 分别得到不同的 1…l 日期整数，原 DATE 亲和性允许这些值；故 Lab 的 `(ID,Date)` 复合 PK 和两个显式 NN 均保持。Date 未被两个查询或其他源约束观察。对它做此代表选择不构成日历转换。
- 全部行和 NULL 模式保持；其余列没有额外源 CHECK/唯一性/外键要求。显式写 0 后由原 affinity 存储，对这些未观察列仍合法。保留行重数避免把合并后的重复 Examination 行误删；Lab 新鲜 Date 又避免了禁止的重复键。
- 对每个父行 p 定义两个条件：SEX='M'，且存在引用它、分别满足 `T-BIL>=2.0` 或 `T-BIL>2.0` 的 Lab 行。固定类别保留每条 Lab 的真假/NULL 情况以及父行 SEX；所有子父关联及行均保留。因此两种合格父键集合分别由同一个单射双射携带，两个 COUNT DISTINCT **各自的整数值**保持。不同 Lab 行造成的遮蔽也保留。

这是比 Δ 保持更强的本例结论，却仍只是手工的本例数学构造。有限代表实例采用原 SQLite 自身语义时，反向可取恒等；该论证没有验证任意 Int/NULL SMT 模型、Polygon 编码或更广 SQL。稿件第 67 行明确保留此边界。每个 N 的构造也没有给出由有界 UNSAT 推出无界 EQ 的 cutoff。
