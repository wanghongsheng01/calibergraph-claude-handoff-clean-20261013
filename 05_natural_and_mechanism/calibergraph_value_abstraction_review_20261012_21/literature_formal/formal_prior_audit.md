# Formal prior audit: finite value abstraction for SQL distinguishability

Analysis only, 2026-10-12. No SQL evaluation, solver run, target import, old-package edit, commit, or push was performed. This note separates source results from a proposed theorem specification and mathematical counterexamples.

**Judgment:** the broad idea “derive a finite abstraction that preserves whether two aggregate outputs agree, rather than preserving their literal values” is established prior art. A useful contribution would need a sharply specified extension, a materially stronger automatically checked certificate, or demonstrated efficiency beyond the established constructions. Combining predicate abstraction, order types, and bounded query encodings is not by itself a novelty argument.

## One precise theorem template to demand

This is a review specification and elementary mathematical derivation, not a claim of a new result or an implemented certificate.

Fix finite schema R, arities `a_R`, and explicit row-occurrence caps `n_R`. Set `m = Σ_R a_R n_R`. Values belong to one mathematical domain Z or Q plus a distinguished NULL. Let C contain **all** non-NULL constants in both queries and every enforced schema constraint.

Admit a typed, deterministic SQL fragment whose nonaggregate expressions are input values or constants; predicates are equality/order and NULL tests under explicit three-valued logic. Bag relational operators, duplicate elimination, and grouping may be used. Terminal aggregates may be COUNT, COUNT DISTINCT, MIN, MAX, provided corresponding output columns in the two queries have the same aggregate operation; copied value outputs must align with copied value outputs. Aggregates cannot feed subsequent expressions or relational operations under this simple template. A broader fragment needs a separate compositional proof.

Let Γ be a finite constraint specification whose truth is invariant under every injective, order-preserving **partial** renaming defined on `adom(D) ∪ C ∪ {NULL}`, fixing C and NULL. This is a finite active-domain embedding condition, not merely invariance under total automorphisms or total embeddings of Z. Equality-based keys/foreign keys, nullability, and explicitly interpreted comparison CHECKs satisfy this property; SQLite expression constraints need separate verification. All tuple occurrences and relations are retained by renaming, so cyclic foreign keys pose no special obstacle to this **value** step.

Construct A from C, NULL, and at most m ordered representatives in each open interval determined by C. Over Z, use `min(m, number of integers in the interval)` representatives; over Q, m suffice in every interval. For every bounded D there is an instance-dependent injection `h_D : adom(D) ∪ C ∪ {NULL} → A` preserving order and fixing constants and NULL. Thus `|A| ≤ |C| + (|C|+1)m + 1` for this one-domain template.

The required conclusion is:

```
D satisfies Γ iff h_D(D) satisfies Γ
Q1(D) =bag Q2(D) iff Q1(h_D(D)) =bag Q2(h_D(D))
```

Proof obligations: (1) interval capacities permit the injection; (2) all primitive truth values are preserved, including UNKNOWN; (3) equality classes and tuple occurrence multiplicities are preserved through relational operations/grouping; (4) COUNT/COUNT DISTINCT retain values while aligned MIN/MAX outputs undergo the same injection; (5) the entire Γ is invariant. The output tuple map is a product of identity maps on count columns and h_D on copied/extremum columns; it is injective. Equality reflection then preserves bag mismatch. Finite enumeration over A is complete **only within the explicit row caps**. A separate small-counterexample theorem is needed to infer unbounded equivalence.

The artifact to certify is a syntax/semantics derivation for these obligations, together with A and the row caps. An unsupported operator, constraint, collation, or type conversion must make the certificate inapplicable. Reporting a finite number of successful tests does not discharge the universal obligations.

## Counterexamples and obstacles

These examples are symbolic arguments, not executed experiments.

1. **A global pointwise finite map cannot preserve arbitrary equality.** Any map from an infinite domain into fixed finite A identifies some `a ≠ b`. Tables R(a), S(b) have no equality-join match, but their mapped images do. A relational equality partition or whole-instance canonical renaming is required. Merely retaining each cell’s comparisons against query literals loses cross-cell equality and order.

2. **Distinct counts and keys expose collapsing values.** R containing two distinct values and S containing one can have COUNT DISTINCT 2 versus 1; collapsing R’s values erases the difference. The same collapse can violate a key. Conversely, treating two duplicate row occurrences as one loses COUNT information. A value-domain bound does not bound multiplicities in bag-valued tables.

3. **Order types alone do not preserve SUM/AVG agreement.** SUMs of bags `{1,1}` and `{2}` agree, but the increasing map `1→2, 2→3` makes them 4 and 3. For AVG, `{1,3}` and `{2}` both average 2; `1→1, 2→2, 3→4` yields 2.5 and 2. These are arithmetic relations beyond order.

4. **Individually safe aggregates need a joint output observation.** On R={2,3}, MIN(R) and COUNT(R) both yield 2. Renaming `2→4, 3→5` preserves equality/order, each aggregate’s own same-aggregate equality behavior, and multiplicity, but yields MIN=4 versus COUNT=2. Cross-aggregate comparison must be proved separately; one option under fixed row caps is to anchor every attainable count, but that is an additional construction and cost.

5. **Schema constants and expressions matter even at one row.** A renaming that moves x=5 to x=6 breaks CHECK(x=5) if 5 was omitted from C. Fixing literal 1 and preserving order still need not preserve CHECK(y=x+1): map `(2,3)` to `(4,6)`. Constraints must be included in the abstraction, not checked only on the eventual chosen representative.

6. **NULL is not an ordinary extra ordered constant.** Predicate evaluation, grouping/distinct equality, aggregate filtering, and CHECK acceptance use different NULL rules. Preserving the NULL pattern plus exact operator semantics can cover a restricted fragment; replacing UNKNOWN with FALSE globally is unsound for CHECK and negation.

7. **Finite input shape does not make a weak abstraction exact.** For fixed row caps and a decidable exact scalar theory, the complete formula `Γ(D) ∧ [Q1(D) ≠ Q2(D)]` may be decidable. Partitioning by its truth value yields a tautological two-class observation quotient. That is not a useful synthesis theorem unless membership/representatives can be obtained without already solving the target problem, with a stated complexity and checking benefit.

SQLite’s documented semantics are additional proof boundaries: values have storage classes; affinity and expression context affect comparisons; dates may be TEXT/REAL/INTEGER; SUM can overflow and uses floating approximations; AVG ignores NULL and interprets nonnumeric text/blob inputs as zero. These require a pinned engine-level semantics or an explicit fragment excluding them. Mathematical Z/Q aggregate theorems do not automatically transfer. [Datatypes, §§2.2, 3.2, 4.2, 6–7](https://sqlite.org/datatype3.html), [aggregates, AVG/COUNT/SUM](https://sqlite.org/lang_aggfunc.html), [date/time functions](https://sqlite.org/lang_datefunc.html).

## Recommendation to the main audit

Treat Cohen–Nutt–Sagiv’s shiftability/ordered-identity construction as the strongest older direct prior. Require a precise delta beyond it and beyond modern SQL checking work. A defensible open question is whether a practical, automatically checked fragment extension preserves **joint query-output distinguishability and every schema constraint** with useful finite representatives and a transparent failure boundary. This audit does not establish that such an extension is novel; it identifies the exact obligations that a novelty and correctness claim would have to survive.

The companion audit is inspecting Cohen’s September 2026 *Few Rows Tell Them Apart* §5; its slot/region construction is a further direct prior and must be considered before choosing a research direction.
