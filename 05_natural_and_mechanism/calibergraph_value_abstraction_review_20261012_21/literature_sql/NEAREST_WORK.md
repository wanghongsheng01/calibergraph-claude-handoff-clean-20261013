# SQL value-abstraction prior-art evidence

Evidence-author memo, 2026-10-12 UTC. Static primary-source review only; no SQL, solver, benchmark, or model execution. Existing local Polygon snapshot read only. This is not an independent challenge decision or a novelty certification.

**Two prior-art threats are decisive for broad claims:** Few Rows already constructs query-pair constant slots with certified separating witnesses in a restricted fragment. Cosette's OOPSLA 2018 refinement already automatically preserves the existence of a pairwise distinguishing output through a proved, query-dependent abstraction. A narrower *finite value-representative construction* must distinguish itself from both, not only from VeriEQL/Polygon.

Context, not extra baseline rows: [HoTTSQL](https://arxiv.org/html/1607.04822v2) and [U-semiring/UDP v3, §§3–5](https://arxiv.org/html/1802.02229v3#S5) supply algebraic, bag/mixed-semantics and integrity-constraint foundations; UDP §6.4 explicitly documents unsupported NULL and scalar arithmetic reasoning in that prototype. [SQLSolver's official artifact](https://github.com/SJTU-IPADS/SQLSolver-artifacts) identifies its LIA-based SQL equivalence mechanism. QED/SQLSolver are relevant alternatives to a finite-domain approach; this memo does not re-audit SQLSolver's entire implementation.

The reviewed evidence rules out three broad novelty claims: (1) first certified query-dependent reduction preserving distinguishing witnesses; (2) first query-constant region partition for mixed set/bag query comparisons; (3) first automatically restricted value domains for SQL verification. It does **not** establish that any reviewed work implements a single reusable finite-value quotient preserving arbitrary SQL output partitions under NULL, bags, aggregates and integrity constraints. That conjunction is not thereby a viable novelty claim: it needs a precise fragment, quantifiers and a proof that differs from the prior mechanisms.

Any remaining hypothesis must state whether it preserves an individual database's output distinction, existence of some witness, or all candidate-pair distinctions simultaneously. It must preserve required equality/disequality multiplicity within an interval, numeric order and gaps for the actual type, NULL/3VL, bag multiplicities, aggregate observations, and legal constraints. These are proof obligations, not an experiment proposal. No positive novelty conclusion is made here.

Evidence limits: author code was read statically, not reproduced or theorem-checked. Current repository commits are not claimed to be the papers' evaluated commits. Few Rows implementation availability remains unverified. No feature-absence conclusion relies on README silence. Full downloaded source files and their SHA256 inventory are adjacent to this memo.
