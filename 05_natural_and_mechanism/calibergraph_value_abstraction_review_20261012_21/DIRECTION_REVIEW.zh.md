## 1. 已有证据实际说明什么

冻结 #1172 的唯一查询差别是 `T-BIL >= 2.0` 与 `T-BIL > 2.0`，结果均为 `COUNT(DISTINCT Patient.ID)`，连接及筛选还观察 Patient/Laboratory 的 ID 和 `SEX='M'`。原始 DDL 为 3 表、64 列，保留 2 项主键声明、3 项显式 NOT NULL、2 项外键；不能删掉未被 SELECT 读取的 Date 复合键或 Examination 外键。

[既有证明](../calibergraph_polygon_adapter_20261012_15/PROOF.zh.md)只覆盖每表至多 1 行、固定 SQL/DDL、标准 SQLite 快照语义。它按**插入后的 SQLite 比较结果**将 T-BIL 分成 NULL/低于/等于/高于阈值，并使用 NULL、0.0、2.0、3.0；单父行让 ID→1 和非空 Date→0 恰好安全。这是手工、逐例的观察保持证明。

[既有实测](../calibergraph_polygon_case1172_20261012_16/RESULT.zh.md)中，Polygon UA 与 precise 均找到同一个经原 SQLite 校验的区分见证：1/0；耗时分别约 0.892s 与 0.399s。故 #1172 支持“真实前端/语义适配边界”，**不支持“强基线不能发现该区别”或“新抽象能带来科学收益”**。这些都是已开发证据，不能重新包装成新测试集。本轮没有新增覆盖率或速度数据。

## 2. 最接近的先例已覆盖哪些核心想法

| 一手先例 | 已有机制及其约束 | 对本轮主张的影响 |
|---|---|---|

## 3. 真正需要解的问题及证书义务

固定 SQLite 版本与内置语义、排序规则、两条查询 Q₁/Q₂、**全部**约束 C、每表行数界 N，以及结果观察协议 Obs（bag/list、NULL、类型和列值如何比较）。令 D(C,N) 为所有合法存储实例，Δ(D) 表示两查询在同一 D 上的观察结果不同。

自动过程需要从 `(Q₁,Q₂,C,N)` 产生有限抽象实例空间 A、抽象语义、可计算映射/提升与可检查证书，并证明：

1. **正向不遗漏：**每个合法 D 都有合法 a∈A，且 Δ(D)=Δ#(a)。
2. **反向不伪造：**每个合法 a 都能提升为合法 D，并保持 Δ；不能先生成悬空外键，再改值修成合法见证。
3. **成本透明：**代表数、证书推导与检查、合法模式判定、求解及最终 SQLite 回放均计入；不能将原求解难度藏进抽象器。

这足以推出两空间中“存在区分见证”等价，是**标准抽象契约的直接推论，不是本轮新定理**。单个真实反例只需正确回放即可支持 NEQ；有界 UNSAT 需要正向完备和完整后端，timeout 不能算通过；没有独立的小模型定理不能外推无界 EQ。

固定行数后，所有相关原子关系的真值模式可以形成经典谓词抽象。但需要包含跨行相等/次序、NULL 规则、分组相等、重数、聚合联合观察及 C。可实现性判断可能与原问题同样昂贵。直接按 Δ 的真/假分成两类更是循环定义，不给出有效求解方法。**仅证明有限商存在不够。**

## 4. 为什么简单分桶在跨行时失效

以下均为纸面反例推导，没有运行 SQL，也不是新增“自然失败样本”。P 表示 Patient(ID,SEX)，L 表示 Laboratory(ID,Date,T-BIL)，其他可空列置 NULL、Examination 为空。原 #1172 的冻结 N≤1 证明不被这些 N>1/新增观察反例推翻。

| 失败点 | 最小说明 | 必须保留的结构 |
|---|---|---|
| ID 碰撞及连接身份 | P={(10,M),(20,X)}；L 分别指向 10 或 20、T-BIL=2。原输出为 (1,0) 或 (0,0)，逐格 ID→1 抹去区别且违反父表 PK。 | 全实例一致的相等类/父子关联；必要时单射重命名。 |
| 未读列的键约束 | 同一 Patient 下两 Lab 行 Date=1、2；Date→0 使复合 PK 冲突。 | 即使列不进 SELECT，也要保留完整 C 所需的不同值。 |
| DISTINCT 与遮蔽 | 同一男性 ID 有 x=2 和 x=3 两行时两查询均为 1；只保留 x=2 则变成 1/0。相同行数分配给两个 ID 又会改变 DISTINCT 计数。 | 行重数、连接等价类和同组竞争见证；不能只看单行谓词差异。 |
| 桶内等号/次序 | 3、4 均在“高于 2”桶；合并会创造相等连接，交换会改变新增跨行排序谓词。 | 原 #1172 的单阈值比较本身不受此问题影响；泛化后须保留联合相等/序型。 |
| 聚合数值关系 | {0,2} 和 {1,1} 的 SUM/AVG 相等；递增映射 0→0、1→1、2→3 后不等。MIN({2,3})=COUNT({2,3})=2，重命名成 {4,5} 后不等。 | SUM/AVG 所需算术关系；不同聚合/常量输出之间统一的相等反射，不能各自使用无关输出映射。 |

SQLite 还需要区分比较语境：affinity 会影响比较，GROUP BY 不做同样的 affinity 转换；外键使用父键的 affinity/collation。因此一个类型无关的“相等关系”不能未经证明同时代理 JOIN、GROUP BY 和 FK。DATE 是亲和性声明，#1172 使用 Date=0 不能推广为日期函数支持。[SQLite 数据类型](https://www.sqlite.org/datatype3.html)、[外键语义](https://www.sqlite.org/foreignkeys.html)。

## 5. #1172 可以怎样跨越 N=1，以及为什么这仍不是新机制

这里给出**未实现、未执行的逐例数学构造**，用于区分“该例存在有限代表”与“有自动、通用且新颖的方法”。它不修改旧 adapter 的 N≤1 范围。

对于固定 `1≤N≤2^63−1`、每表至多 N 行的合法 #1172 实例，在既有标准 SQLite 快照/完整 C 前提下：

- 将所有 Patient ID **单射**编号为 1…k；每个非 NULL 子 ID 按其原来匹配的父行编号重命名，Examination 的 NULL ID 保留。
- 保留全部行及 NULL 模式。SEX 和 T-BIL 仍按原存储值的 SQLite 谓词观察分类；不要按 Python 数值猜测。
- 将每条 Lab 的 Date 赋为不同的 1…l，保持复合键及非空性。Date 不被这两条查询观察，也无其他源约束引用它。
- 其余未观察非 NULL 单元写入字面量 0，由原 DDL 的 affinity 归一化；NULL 保留。原表、列、默认及级联声明保留，全部列显式插入；不执行级联更新/删除。

**证明概要：**父键单射、各 Lab Date 不同，所以两个 PK 保持；非空性和父子指向保持，所以完整 NN/FK 保持。原 ID 是整数主键，合法非 NULL Lab ID 的 FK 匹配与本查询连接一致。每条 Lab 的两阈值谓词和其父行的 SEX 谓词不变，每个符合条件的 Patient ID 集合被双射携带；因此两 COUNT DISTINCT 值各自保持，多个 Lab 行间的遮蔽关系也保留。列值均来自随 N 有限的代表集合。合法有限代表实例本身就是原 SQLite 实例，反向提升可取恒等；这**不**证明任意 SMT 编码模型也可直接提升。

该构造说明 #1172 的 N=1 障碍主要来自旧映射将键值全部压成 1，而非这个查询天然只能在 N=1 获得有限代表。修成联合键重命名和新鲜 Date 只是经典结构保持技巧。困难尚在于：自动识别何种 SQLite 观察与 C 允许这种构造，证明其他操作/聚合也可组合，并给出比直接符号编码更有价值的复杂度或实证结果。本轮没有得到这一新增构造或定理。

## 6. 为什么现在停止

最强的可辩护表述是“原 SQLite 语义相对现有工具建模存在适配空隙”；尚无证据支持“这个空隙需要新的科学机制”。已有先例覆盖泛化目标、主要构造工具和认证路线；新引入的 SQLite 条件目前只是待实现/待证明清单。把三者相加不足以通过新颖性门槛。

因此本轮不留下命名候选、不指定实现任务、不安排新 SQL/solver 实验，实验预算为 **0**。未来若有实质新证据才重新评审：至少要给出先例尚不覆盖的明确片段、非循环的自动构造、正确性/完备性命题及有意义的成本界。已有 #1172 等暴露样本只能用于开发；确认集仍须独立。将来若比较，应先共享正确前端与相同 C/N/观察协议，再比较直接精确编码、已有 choice/provenance 缩减、经典联合序型构造与新增部分，计入全部预处理和失败分母；这只是重新开启时的公平性条件，**不是获准运行的实验方案**。
