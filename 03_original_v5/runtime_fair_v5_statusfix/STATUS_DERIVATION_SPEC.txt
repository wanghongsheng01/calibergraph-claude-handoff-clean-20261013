Pair-work receipt specification v1 — logging only

There are four independent layers: (1) query dispatch execution, (2) raw algorithm/solver/SQL outcome, (3) semantic validation, (4) process/resource acknowledgement. RETURNED is exclusively layer 1. It is never a synonym for UNSAT, correct, verified, or normal process exit.

FUTURE WRITE RULES
The worker persists pair_work_started=True and ATTEMPTED_EFFECT_UNKNOWN immediately before entering the existing query branch. At the actual common dispatch-return point, before cleanup, record_pair_receipt(DISPATCH_RETURNED) writes RETURNED only if started is exactly True, final_decision is not NOT_RUN, and no attempt/fallback/differential/oracle slot remains in an ATTEMPT/RUNNING marker. Missing final outcome or pending outcome gives RETURNED_INCOMPLETE_RECEIPT. Return without started gives INCONSISTENT_RETURN_RECEIPT. No final semantic-validation flag is derived by this helper.
Unknown, unsupported, unsafe int64 oracle domains, replay mismatches and ineligible differential outcomes can return normally as execution, retaining their original non-success result. Canonical AST identity is explicitly not a pair-solver receipt. Per-query differential UNSAT is explicitly not pair equivalence. Merely observing a prior attempt.status=sat cannot complete an unfinished oracle.
A contract stop before dispatch is NOT_RUN_CONTRACT_STOP. A late contract stop is RETURNED_WITH_CONTRACT_STOP and preserves prior attempts. Error before dispatch is NOT_RUN_ERROR; after dispatch it is RETURNED_WITH_ERROR. A cleanup error preserves the prior dispatch return receipt nested under prior_receipt. Frontend stop before dispatch is NOT_RUN_FRONTEND_STOP. Hard termination that never reaches a callback leaves the last ATTEMPTED_EFFECT_UNKNOWN untouched.
The supervisor copies the pair_work_started/status/receipt fields but retains its independent strict completion rules. Every local receipt says PENDING_SUPERVISOR_ACKNOWLEDGEMENT and NOT_INFERRED_FROM_EXECUTION_RECEIPT for scientific validation. No success, solver decision, oracle value, error or stop_reason is rewritten. Added durable logging has overhead; future statusfix timings belong to this distinct source-lock cohort and cannot silently replace old-v5 cost samples.

HISTORICAL DERIVATION RULES — ADD FIELDS, NEVER REWRITE RAW
Each selected or alternative attempt must keep raw_pair_work_status and a separate derived object with rule version, source absolute path AND SHA, original worker phase/status/started/final decision, supervisor path/SHA, recorded/observed worker SHA and slot identity. An unselected alternative is retained; no latest-wins selection.
1. started must be exactly True to derive any pair RETURNED state. COMPLETE + FINAL_COMPLETE with missing/False started => NO_PAIR_RETURN_RECEIPT, not RETURNED.
2. started=True AND worker status COMPLETE AND phase FINAL_COMPLETE establishes a worker dispatch-return receipt only. Preserve the raw result and audit pending outcome markers separately. Any pending oracle/attempt prevents a complete outcome/validated-success inference.
3. started=True AND BLOCKED_OR_ERROR + ERROR => RETURNED_WITH_ERROR; typed final contract-stop receipt with started=True => RETURNED_WITH_CONTRACT_STOP. Before-start typed stops remain NOT_RUN_CONTRACT_STOP. Preserve late attempts and cleanup errors.
4. Old52 worker phase OFFICIAL_ATTEMPT/status NOT_RUN with no final receipt remains ATTEMPTED_EFFECT_UNKNOWN, even though its original contract was audited. Its last 1.234137 CPU-second checkpoint is not final cost; initializing sampled RSS=0 is not a measured zero.
5. Process acknowledgement is separate: require the correct supervisor selected slot, hash-matching worker, same suite/runtime/program identities, terminal PROCESS_EXITED, no stop_reason KEY (even an empty-valued key is a recorded stop marker), known exit code, and expected worker final receipt. exit0 + worker COMPLETE alone is insufficient. RESOURCE_STOP or RSS_OBSERVATION_UNAVAILABLE never becomes strict normal completion.
6. Validated SAT additionally needs full contract/bridge guards and the final result-carrying attempt's completed original-C, safe-int64, unequal-original-SQL replay (for cost pair), with matching outcome and no pending oracle. Differential SAT is not a cost-pair SAT. Validated cost UNSAT requires a returned final result-carrying solver attempt or the actual admitted canonical identity receipt, plus common gates; do not use an earlier abandoned attempt. Unknown/unsupported/rejected/unsafe/error outcomes are never promoted. The status helper deliberately makes none of these scientific validation decisions; the independent aggregator must apply them separately.
7. Current reported observation-stop identities include old cost19/39/51 and later cost83/diff28/diff44. These are examples, not an exhaustive hardcoded exclusion list: inspect every selected and alternative slot's actual resource receipt.
