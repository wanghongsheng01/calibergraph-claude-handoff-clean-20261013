## Mandatory strongest controls

Use a single shared semantics contract and account for end-to-end time, including database legality checks, query replay, parsing, encoding, cache lookup, compilation, and witness validation. Equality scope includes bound, SQL dialect/NULL/bag/order semantics, schema/IC fingerprint, and tool version.

1. **Persistent process + shared schema/IC + incremental solver:** common base asserted once, query-specific obligations in push/pop scopes or activation assumptions; parsed AST and safe query encodings reused. Report separately from cold process latency.
2. **Exact and semantics-preserving result caches:** exact query-pair/contract keys, symmetric pair normalization, and validated canonical forms; compatible implication/subsumption reuse where sound. UNSAT transfer needs the entailment direction and same semantic scope; unknown/timeouts are never proofs.
3. **Fair replay-all witness cache:** every method gets the same legal historical databases, replays all relevant pending pairs before new solving, validates full current C, and caches each query's result on each database. Charge all replay costs. A concrete witness refutes only pairs whose actual outputs differ; past witness origin is irrelevant. No future/held-out witness leakage.
4. **Query-specific reusable test suites:** XData-style mutant suites and distilled/ParSEval-style query-generated suites, replayed on new submissions/versions. Coverage selection/set cover is a baseline, not the proposed novelty.
5. **Polygon joint objective:** same pending pair set under a joint output condition, or its documented disambiguation objective when appropriate. An impossible all-pair conjunction must not be reported as all pairs equivalent. Also include bounded-budget selection of satisfiable goals rather than comparing only to serial pair checks.
6. **Ordering/portfolio control:** same resource budget, static schema grouping and several deterministic/random orders, common warm-up/cache state. Batch order and persistent imports are engineering controls. This audit did not find or exhaustively rule out every official experiment scheduler.

The parent cost inventory reports schema+IC and encode totaling about 1.565% of eight already exposed Polygon slots, while import+parse is about 58.92%. This audit did not recompute those measurements. They further weaken any scientific claim built only on removing initialization overhead.

## At most one unresolved mechanism boundary

The only candidate boundary retained for the designer is **constructing a new simultaneous witness algebraically inside one independently certified full-C legal Cartesian region**, with fixed row/NULL/join behavior and polynomial aggregate mismatches. Neither cross-pair replay nor a joint SMT objective is the delta. No direct implementation of that exact construction was found in the eight scoped source files. This is **not a novelty finding**.

The mathematical step “all nonzero P_i can be made nonzero simultaneously” immediately reduces to nonvanishing of their product over a sufficiently large legal grid. It is threatened by standard polynomial identity/root-avoidance arguments and the existing Few Rows manuscript's multiplicity-polynomial/grid reasoning (§5; local primary fewrows.text.txt lines 1908–2271). [Few Rows primary preprint](https://arxiv.org/html/2609.09978v1). Few Rows concerns relational multiplicities and specified dense-order/constraint classes; it does not directly prove a generic aggregate-SQL batch reuse theorem. Novelty cannot rest on the product trick. The unresolved hard part is a nontrivial, economical certificate that an entire region obeys full C and the intended SQL piecewise semantics, plus a generation algorithm with a demonstrable advantage after certification/replay costs. If region certification merely invokes the same joint solver or constructs the answer in advance, or if ordinary random legal databases/PIT and replay-all explain the gain, reject.

No claim of first batch SQL verification, first multi-query counterexample, first witness sharing, first query-version reuse, first proof cache, first IC sharing, or first coverage-based witness scheduling is supported.

## Evidence limits

No SQL, solver, training, or manuscript execution/edit was performed. Source discovery used rg; selected code was read and byte hashes checked. Positive source findings are strong; absent mechanisms are limited to the listed source files/paths, not the repositories or literature as a whole. A publisher record for Aquino et al., *Reusing constraint proofs in program analysis*, ISSTA 2015, DOI 10.1145/2771783.2771802, was located but not used as evidence of a detailed mechanism. No novel mechanism is cleared for experiments by this audit alone.
